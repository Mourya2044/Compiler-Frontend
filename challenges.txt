Root cause:

In grammar.cpp, DeclList has an epsilon rule.
In grammar.cpp, Stmt can also start with Decl.
That makes int and float belong to FOLLOW(DeclList), so in states 5 and 6 the parser can either:
reduce by r2: DeclList -> epsilon
shift into Type: int/float
SLR uses FOLLOW sets for reduce lookaheads, so this grammar shape creates shift/reduce conflicts there.
What the reported conflicts mean:

r2 is DeclList -> epsilon.
s9 and s10 are shifts on float and int.
So the parser is undecided whether declarations are over, or another declaration starts.
How to eliminate conflicts:

If you want C-like style (all declarations before statements):
Keep Program -> ... DeclList StmtList ...
Remove Stmt -> Decl from grammar.cpp
If you want declarations anywhere in a block:
Replace separate DeclList and StmtList split with a single list of block items.
Example shape:
Block -> { ItemList }

Alternative without grammar rewrite:
Switch from SLR to canonical LR(1), which often resolves these FOLLOW-based spurious conflicts.
